# 🔬 Анализ ограничений SAST-движка tg-flowmap (Кейс: pc-control)

> **Документ составлен по результатам реального аудита бота `pc-control` (`vds_bot`)**.  
> Анализ выявил слепые зоны статического AST-парсера при работе со сложными асинхронными, IoT и событийно-ориентированными Telegram-ботами.

---

## 📋 Сводка обнаруженных проблем

| # | Проблема / Ограничение | Проявление в `pc-control` | Влияние на граф | Ложное срабатывание |
|---|---|---|---|---|
| **1** | **Динамические `callback_data` (f-строки)** | `f"ag_switch:{acc_id}"`, `f"flow_workspace_vpn:{vpn}"` | Кнопки не связываются с роутерами `startswith("ag_switch:")` | `[DANGLING_HANDLER]` (42 шт.) |
| **2** | **Параметризованные клавиатуры-карточки** | `def antigravity_card_markup(self, data: dict)` | Клавиатура извлекается, но не привязывается к вызывающему экрану | `keyboard: None` у 74 узлов |
| **3** | **Асинхронные брокеры и диспетчеры (MQTT/EDA)** | Сообщения отправляются из `mqtt_dispatcher.py` при ответе от ПК | AST-парсер не видит `send_message`, вызванный по событию брокера | Потеря связи экрана с клавиатурой |
| **4** | **Корневые хабы в `[MISSING_BACK]`** | Команда `/exit` отправляет `main_menu_markup` | Линтер требует кнопку «Назад» даже на экране, который сам является Главным меню | `[MISSING_BACK]` на `/exit` |
| **5** | **ООП-миксины (`UiMarkupsMixin`)** | Вызовы через `app.ui.power_menu_markup()` | Парсер дублирует клавиатуры (`UiMarkupsMixin.x` и `x`) | Рассинхрон алиасов клавиатур |
| **6** | **Сквозные FSM-сценарии (State Machines)** | Оркестровка питания (WoL -> пинг -> анлок -> VPN) | Граф показывает атомарные клики, но не видит цепочку шагов воронки | Отсутствие визуализации сценария |

## 🔍 Детальный разбор краевых случаев

### 1. F-строки и параметризованные `callback_data`
* **Проблема:**  
  В реальных production-ботах данные в кнопках почти никогда не бывают статическими строками. Используются префиксы с идентификаторами:
  ```python
  # ui_markups.py
  InlineKeyboardButton(text="Профиль", callback_data=f"ag_switch:{acc_id}")
  ```
  В роутере:
  ```python
  # antigravity_router.py
  if data.startswith("ag_switch:"):
      ...
  ```
* **Как повёл себя tg-flowmap:**  
  `AstParser` видит шаблон `ag_switch:*` в роутере, но внутри f-строки `ast.JoinedStr` не может вычислить `acc_id` во время AST-анализа. В результате кнопка остаётся без связи с обработчиком, а обработчик объявляется «висячим»:
  > ℹ️ `[DANGLING_HANDLER] Обработчик 'ag_switch:*' определён в коде, но ни одна кнопка на него не ссылается.`

### 2. Динамические карточки с аргументами (`data: dict`)
* **Проблема:**  
  Интерфейс строится на основе живого состояния системы:
  ```python
  def antigravity_card_markup(self, data: dict) -> dict: ...
  def player_card_markup(self, media_state: dict) -> dict: ...
  ```
* **Как повёл себя tg-flowmap:**  
  Парсер успешно зарегистрировал функцию как клавиатуру, но не смог понять, какому именно экрану она принадлежит. Роутер только инициирует фоновый запрос, а разметку собирает диспетчер ответов. В графе узел остался с `keyboard: None`.

### 3. Межмодульный dispatch через брокер сообщений (EDA / MQTT)
* **Проблема:**  
  В архитектуре IoT-ботов Telegram-интерфейс отделен от бизнес-логики:
  1. Пользователь жмёт кнопку в Telegram (`antigravity_router.py`).
  2. Бот публикует MQTT-команду на Desktop-агент: `app.mqtt.publish_desktop_action(...)`.
  3. Десктоп выполняет действие и возвращает JSON-ответ в MQTT-топик.
  4. Входной обработчик брокера `mqtt_dispatcher.py` ловит ответ и вызывает `app.ui.send_message(chat_id, text, reply_markup=...)`.
* **Как повёл себя tg-flowmap:**  
  SAST-парсер ищет вызовы `send_message` или `edit_message_text` **строго внутри локального AST-дерева текущего хэндлера**. Асинхронный разрыв контекста через очередь сообщений полностью скрывает отправку клавиатуры от статического анализа.

### 4. Ложный `[MISSING_BACK]` на Главном меню
* **Проблема:**  
  Команда `/exit` или клик «В меню» сбрасывает режим и возвращает пользователя в Главное меню:
  ```python
  # command_router.py:101
  if lower_text in {"/exit", "выход"}:
      app.ui.send_message(chat_id, "Консоль закрыта", reply_markup=app._main_menu_markup())
  ```
* **Как повёл себя tg-flowmap:**  
  Линтер проверяет: *«Содержит ли отправленная клавиатура кнопку со словом 'назад' или 'меню'?»*. В `main_menu_markup` такой кнопки нет, потому что **это и есть корень**. Анализатор выдал предупреждение:
  > ⚠️ `[MISSING_BACK] В экране '/exit (выход)' нет кнопки возврата (« Назад / В меню »). Пользователь может оказаться в тупике.`

## 🛠 Дорожная карта улучшений (Roadmap для tg-flowmap)

### Этап 1. Интеллектуальный Pattern-Matching для F-строк (Quick Win)
- [x] При разборе `ast.JoinedStr` заменять неразрешимые выражения (`ast.FormattedValue`) на wildcard-шаблон `*`.
  - Пример: `f"ag_switch:{acc_id}"` ➔ трансформировать в AST-литерал `"ag_switch:*"`.
- [x] В `GraphAnalyzer` связывать кнопки с шаблоном `"ag_switch:*"` напрямую с роутерами `data.startswith("ag_switch:")`.
- **Эффект:** Снятие ~30 ложных предупреждений `[DANGLING_HANDLER]`. *(Реализовано)*

### Этап 2. Распознавание корневых экранов (Root Hub Filter)
- [x] Если отправляемая экраном клавиатура совпадает с клавиатурой `/start` или `cb:menu` (`main_menu_markup`), подавлять проверку `MISSING_BACK`.
- **Эффект:** Устранение ложных предупреждений на командах выхода, отмены и возврата в меню. *(Реализовано)*

### Этап 3. Анализ вызовов через ООП-миксины
- [ ] Разрешать вызовы вида `self.ui.<method>()` и `app.ui.<method>()` к методам классов `UiMarkupsMixin`, `TelegramUI` и т.д.
- [ ] Унифицировать реестр клавиатур: не создавать раздельные дубликаты `ClassName.method` и `method`.

### Этап 4. Двухпроходное связывание диспетчеров (Event-Driven Tracing)
- [ ] Добавить в `AstParser` глобальную карту вызовов `send_message / edit_message_text` по всему проекту (включая вспомогательные сервисы `mqtt_dispatcher.py`, `background_workers.py`).
- [ ] Связывать зарегистрированные клавиатуры с хэндлерами по именам методов (`antigravity_card_markup` ➔ экран `antigravity_menu`).

### Этап 5. Поддержка FSM-цепочек (State Machine / User Flow)
- [ ] Распознавать шаги FSM (`state=Step.xyz`) и связывать последовательные экраны сценариев («Рабочий сетап» ➔ «Пинг» ➔ «Анлок» ➔ «Готово») в единые визуальные коридоры на интерактивном холсте.
